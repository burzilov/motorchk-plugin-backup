# Резервные копии для motorchk

Независимый плагин для ядра motorchk ≥ 0.4. Код плагина можно публиковать открыто; **архивы всегда приватны**. Первая версия создаёт полные ZIP-копии файлов сайта вручную из админки, показывает список, позволяет скачать и удалить архив. Расписание и внешнее хранилище пока не предусмотрены.

## Что попадает в ZIP

**Всё в корне сайта, кроме `core/`**, включая `.env`, `.htaccess`, `config/`, `content/`, `media/`, `themes/`, `plugins/`, `plugin-data/`, `submissions/`, `cache/` и любые добавленные владельцем файлы и папки. Пустые папки сохраняются. Символические ссылки и специальные файлы вызывают ошибку вместо чтения файлов за пределами сайта. Резервные копии находятся вне сайта и поэтому не архивируют сами себя.

Архивы могут содержать пароли, токены и персональные данные. **ZIP не зашифрован**; не публикуйте его в Git, в веб-папке или в открытом облаке. Изменение файлов во время копирования может сделать снимок несогласованным: плагин обнаруживает изменения списка, размеров и времени файлов и отменяет такой архив, но для строгой согласованности при высокой нагрузке нужны остановка записи или снимок файловой системы. Внешние БД и файлы, которые физически хранятся за пределами корня сайта, не включаются.

## Установка и создание

Положите исходники в `plugins/backup/`, включите плагин в админке и откройте «Резервные копии». Требуется PHP-расширение `zip`, достаточно свободного места и право PHP создавать закрытую папку рядом с корнем сайта. По умолчанию архивы хранятся в `../motorchk-backups-{имя_папки_сайта}/` с правами `0700`, ZIP — `0600`. Можно задать **абсолютный путь вне сайта** через `MOTORCHK_BACKUP_DIR` в `.env`; родительская папка должна существовать. Архив формируется во временном файле и становится доступен только после проверки и атомарного переименования.

Для больших сайтов веб-запрос может превысить лимит времени веб-сервера. Из CLI можно создать копию, не зависящую от HTTP:

```bash
php plugins/backup/bin/create.php /absolute/path/to/site
```

## Перенос на другой хостинг

1. Разверните **совместимую версию ядра** в `новый-сайт/core/` (номер исходного ядра записан в комментарии ZIP), установите зависимости ядра.
2. Распакуйте ZIP **в корень сайта**, не внутрь `core/`: `unzip backup-….zip -d /path/to/новый-сайт`. Содержимое `core/` архив не перезапишет.
3. Настройте на новом сервере PHP и веб-сервер, права на запись в `cache/`, `content/`, `submissions/`, `plugin-data/` и `media/`; проверьте `.env`, домен и любые пользовательские абсолютные пути в `config/site.php` и настройках плагинов. Если используется внешний сервис (например SMTP), настройте доступ к нему.
4. Проверьте сайт и админку **до переключения DNS**. Сохраните первоначальный архив отдельно.

Плагин не восстанавливает архив поверх работающего сайта — это опасно для заказов и других живых данных. Развёртывание выполняется в новой директории.
