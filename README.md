# Резервные копии для motorchk

Независимый плагин для ядра motorchk 0.5.x (`"core": "^0.5"`). Код плагина можно публиковать открыто; **архивы конфиденциальны и всегда приватны**. Плагин создаёт полные ZIP-копии файлов сайта вручную из админки или CLI для быстрого и полного восстановления после краха, показывает список, позволяет скачать и удалить архив, хранит последние N копий. Расписание и внешнее хранилище пока не предусмотрены.

## Что попадает в ZIP

**Всё в корне сайта, кроме `core/` и содержимого `cache/`**, включая `.env`, `.htaccess`, `config/`, `content/`, `media/`, `themes/`, `plugins/`, `plugin-data/`, `submissions/` (заявки) и любые добавленные владельцем файлы и папки. `.env` и заявки входят намеренно — без них сайт не восстановить полностью. Папка `cache/` попадает в архив пустой: кэш ядро пересоздаёт само, а его постоянные изменения мешали бы проверке согласованности снимка. Пустые папки сохраняются. Символические ссылки и специальные файлы вызывают ошибку вместо чтения файлов за пределами сайта. Резервные копии находятся вне сайта и поэтому не архивируют сами себя.

**Архивы конфиденциальны**: в них пароли и ключи из `.env` (SMTP, API), хэш пароля администратора, токены и персональные данные клиентов из заявок. **ZIP не зашифрован**; храните и передавайте его как секрет, не публикуйте его в Git, в веб-папке или в открытом облаке. Изменение файлов во время копирования может сделать снимок несогласованным: плагин обнаруживает изменения списка, размеров и времени файлов и отменяет такой архив, но для строгой согласованности при высокой нагрузке нужны остановка записи или снимок файловой системы. Внешние БД и файлы, которые физически хранятся за пределами корня сайта, не включаются.

## Установка и создание

Положите исходники в `plugins/backup/` (или распакуйте архив релиза в `public_html/plugins/`), включите плагин в админке и откройте «Резервные копии». Требуется PHP-расширение `zip`, достаточно свободного места и право PHP создавать закрытую папку рядом с корнем сайта. По умолчанию архивы хранятся в `../motorchk-backups-{имя_папки_сайта}/` с правами `0700`, ZIP — `0600`. Можно задать **абсолютный путь вне сайта** через `MOTORCHK_BACKUP_DIR` в `.env`; родительская папка должна существовать. Архив формируется во временном файле и становится доступен только после проверки и атомарного переименования.

## Ротация

После каждой успешно созданной копии хранятся только последние N архивов (по умолчанию 10); более старые удаляются. `MOTORCHK_BACKUP_KEEP` в `.env` задаёт N (целое 1–9999; неверное значение — ошибка). Удаляются только файлы вида `backup-<UTC>-<hex>.zip` в папке копий; другие файлы там не трогаются. Нужную копию надолго сохраните вне этой папки.

Ошибка удаления в админке показывается общим текстом, подробности — в журнале ошибок PHP.

Для больших сайтов веб-запрос может превысить лимит времени веб-сервера. Из CLI можно создать копию, не зависящую от HTTP:

```bash
php plugins/backup/bin/create.php /absolute/path/to/site
```

## Перенос на другой хостинг

1. Разверните **совместимую версию ядра** в `новый-сайт/core/` (номер исходного ядра записан в комментарии ZIP), установите зависимости ядра.
2. Распакуйте ZIP **в корень сайта**, не внутрь `core/`: `unzip backup-….zip -d /path/to/новый-сайт`. Содержимое `core/` архив не перезапишет.
3. Настройте на новом сервере PHP и веб-сервер, права на запись в `cache/`, `content/`, `submissions/`, `plugin-data/` и `media/`; проверьте `.env`, домен и любые пользовательские абсолютные пути в `config/site.php` и настройках плагинов. Если используется внешний сервис (например SMTP), настройте доступ к нему.
4. Проверьте сайт и админку **до переключения DNS**. Сохраните первоначальный архив отдельно.

Плагин не восстанавливает архив поверх работающего сайта — это опасно для заказов и других живых данных. Развёртывание выполняется в новой директории.

## Релиз

`./release.sh` — релиз: проверяет чистое дерево и что первая запись CHANGELOG.md совпадает с version в plugin.json, ставит аннотированный тег `v<версия>` и собирает `dist/backup-<версия>.zip` из тега (`git archive`). `./release.sh --push` — ещё и `git push` коммитов и тега в origin. Тег — точная ссылка на код развёрнутой версии: по нему видно, что стоит на сайте, и можно собрать тот же архив или сравнить версии (`git diff v0.1.0 v0.2.0`). У репозитория нет origin — `--push` не нужен.
